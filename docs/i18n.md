# Infrastructure i18n

Cette première étape installe un socle i18n léger et typé, sans modifier le rendu, les formulaires ou les routes existantes. Elle n'ajoute aucune dépendance : le chargement dynamique des dictionnaires repose sur TypeScript et Next.js.

## Langues

| Locale | Libellé | Drapeau | Langue HTML cible |
| --- | --- | --- | --- |
| `fr` | Français | 🇫🇷 | `fr-HT` |
| `en` | English | 🇺🇸 | `en` |
| `es` | Español | 🇪🇸 | `es` |

La langue par défaut est `fr`. Les constantes, le type `Locale`, les libellés et `isValidLocale` sont définis dans `src/i18n/locales.ts`.

## Structure

```txt
src/i18n/
  index.ts
  locales.ts
  routing.ts
  messages.ts
  messages/
    fr.json
    en.json
    es.json
```

- `locales.ts` est la source de vérité des locales.
- `routing.ts` résout une locale et construit un chemin préfixé en conservant query string et ancre.
- `messages.ts` charge dynamiquement un seul dictionnaire et expose son type.
- Les JSON contiennent les namespaces initiaux `common`, `navigation`, `footer`, `home`, `services`, `contact`, `consultation`, `academy` et `seo`.
- `index.ts` fournit le point d'entrée public du module.

## Utilisation

```ts
import { getLocalizedPath, getMessages, isValidLocale } from "@/i18n";

const locale = isValidLocale(candidate) ? candidate : "fr";
const messages = await getMessages(locale);
const servicesUrl = getLocalizedPath("/services?source=home", locale);
```

`getLocalizedPath` prépare les futures URLs `/fr`, `/en` et `/es`, mais ne garantit pas que la route cible est déjà publiée. Le sélecteur de langue devra consulter un registre de disponibilité avant de naviguer et revenir vers `/{locale}` si l'équivalent n'existe pas.

## Ajouter ou modifier une traduction

1. Choisir le namespace fonctionnel approprié.
2. Ajouter la même clé aux trois JSON ; le fichier français définit la forme TypeScript attendue par les autres chargeurs.
3. Employer une clé sémantique telle que `navigation.home`, jamais la phrase française comme clé.
4. Garder hors des dictionnaires les identifiants métier, slugs, endpoints, noms de champs et valeurs envoyées aux API.
5. Exécuter `npm run lint` et `npm run build`. Le build TypeScript détecte notamment une structure incompatible dans un dictionnaire chargé.

Pour ajouter une langue, il faudra ajouter son code à `locales`, sa configuration dans `localeConfig`, son JSON, puis son loader dans `messages.ts`. Une future PR devra également déclarer ses routes et ses metadata SEO.

## Limites actuelles

- Les routes publiques historiques restent volontairement non préfixées et continuent à fonctionner telles quelles.
- Les chemins `/fr`, `/en` et `/es` ne sont pas encore montés : publier des pages françaises sous un préfixe étranger créerait un mauvais signal SEO.
- Aucun composant ne consomme encore les dictionnaires ; le site visible reste intégralement inchangé.
- `<html lang>`, canonical, Open Graph, sitemap et `hreflang` restent ceux du site français actuel.
- Il n'y a encore ni middleware de détection, ni cookie de préférence, ni sélecteur de langue.
- Les contenus éditoriaux Supabase (articles et cours) n'ont pas de modèle de traduction et ne sont pas modifiés.
